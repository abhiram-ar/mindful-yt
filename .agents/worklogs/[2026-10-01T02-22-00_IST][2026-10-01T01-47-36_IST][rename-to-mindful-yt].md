# Renamed from ytget to mindful-yt

On 2026-10-01 the command was renamed from `ytget` to `mindful-yt`. That
covers the binary, `cmd/mindful-yt/`, the release files
(`mindful-yt_<os>_<arch>`), the install scripts and the interface text.

**The user then renamed the GitHub repo to `mindful-yt`,** so the Go module path is
now `github.com/abhiram-ar/mindful-yt` (it was
`.../youtube-downloader-via-dns-over-http`). `go install` needs the module path
to match the repo. The git remote points at the new URL; GitHub redirects the
old one.

Worklogs written before the rename use the old name, because they describe
history.

## What changed besides the name

- **Data folders move on first run.** `store.Dirs` calls `adopt`, which renames
  an existing `ytget` folder to `mindful-yt`, but only when the new folder
  doesn't exist. That covers the settings folder (`%APPDATA%`, `~/.config`,
  `~/Library/Application Support`) and the tools folder (`%LOCALAPPDATA%`,
  `~/.cache`, `~/Library/Caches`), so history, today's count and yt-dlp carry
  over.
  - If the rename fails, e.g. because a running `ytget` has a file open, the
    old folder keeps being used.
  - `--version` runs before `Dirs`, so it never moves anything. Every other
    command, including `--help`, can.
- **Environment variables:** `YTGET_*` became `MINDFUL_YT_*`
  (`MINDFUL_YT_HOME`, and for the scripts `MINDFUL_YT_VERSION`,
  `_INSTALL_DIR`, `_BASE_URL` and `_NO_PATH`), because variable names can't
  contain `-`. The old names are no longer read.
- **Internal names:** the yt-dlp output markers (`mindful-yt-progress`,
  `-formats`, `-done`), the proxy's username and realm, and temp file prefixes.
- **Fitted header:** the longer name made the header line exceed a
  30-column terminal. The header now goes through `fit()` like every other line.

## Checked

- Tests pass on Windows, and vet passes on Windows, Linux and macOS.
- `adopt` has tests for moving an old folder, never replacing an existing new
  folder, and creating nothing on a fresh install.
- A GoReleaser snapshot builds `mindful-yt_*` archives.
- Both install scripts pass a fresh install, an update, a tampered checksum
  and a missing file.

## The sandbox showed a different AppData

- **The agent's sandbox had its own view of AppData.** The agent's `adopt`
  run renamed `ytget` to `mindful-yt`, but only in its own view. The user's
  real AppData still had only `ytget`, with 6 history entries. The evidence:
  the user's backup at 02:17 contained only `ytget`.
  - Since the first session, the agent's view had also held a separate
    3-entry history: the Python-era entries, moved there in session 1.
  - `dangerouslyDisableSandbox` didn't give a different view.
- **The user ran a merge script in their own terminal.** It stopped the
  processes and backed up the folders to `~\mindful-yt-backup-*` (two runs:
  02:17 and 02:18). It then merged both histories into `mindful-yt` with
  ytget's config, removed the `ytget` settings folder, and renamed the tools
  folder to `mindful-yt`.
