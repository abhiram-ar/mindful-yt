# Searching YouTube, and listing a channel's videos

Two ways to find a video without leaving the terminal, both built
2026-10-03:

1. **Search.** Text that isn't a YouTube video link searches YouTube. The
   results are listed in YouTube's relevance order.
2. **A channel's newest videos.** Input that's just `@<handle>` lists that
   channel's latest uploads, newest first.

Picking a video goes on as if its link had been pasted, so the guardrails
(daily limit, reason) are unchanged.

## The user's decisions

- **Rows** show the title, the channel's **handle** (`@jawed`), the **views**,
  the age **in YouTube's words** ("3 weeks ago"), and the length.
  - **No likes:** search results don't carry them. Each would need a full
    lookup per video (2–4 s).
  - **The handle only when YouTube gives it**, otherwise the channel name.
    It's yt-dlp's `uploader_id`, which was missing for about half the
    results in some searches (none for Lofi Girl or officialpsy). Looking
    it up from the always-present channel ID would cost a request per
    channel, and the user declined that.
  - Channel lists leave the channel out of each row, since it's the same
    for every video.
- **How many:** `search_results` in config.json, **default 15**. Below 1
  becomes 15, and anything above 50 is capped at 50 (`maxSearchResults`).
  The same number applies to channel lists.
- **Daily limit used up:** the search or channel list is refused before it
  runs, like a pasted link. Listing never counts toward the limit.
- **The list is bubbles' `list`** (v2.2.1), in mindful-yt's look. Only its
  rows and page dots show; our header, heading and help line stay.
- **`@handle` means the handle, not the channel's name.**
- **"Load more" is not built.** Still the user's call.
  - `ytsearchN` is "the first N", with no offset, and a continuation token
    can't be carried between yt-dlp runs.
  - A second run with `-I 11:20` refetches from page 1, and YouTube may
    reorder in between, so a video can be skipped.
  - Only fetching more in one run is fully reliable.

## How it works

- **Routing** (`tui.acceptLink`, for the box and the CLI positional):
  1. `link.Handle`: input that's exactly `@` plus 3–30 letters (any
     script), digits, `_`, `-` or `.` lists that channel. `@jawed zoo`
     isn't a handle, so it's searched.
  2. `link.Canonical`: a single-video link gives today's flow.
  3. `ErrNotSingleVideo` keeps today's refusal (playlists, channel *links*,
     results pages). Single videos only.
  4. `ErrNotYouTube` searches. That covers words and other sites' links.
     Empty input gives a problem line.
- **The flow:** `startSearch` and `startChannel` go through `startList`, then
  `startDownloadFlow` (limit, then the tools check). `depsChecked` with
  `watchURL == ""` calls `fetchList`. Picking a video calls
  `acceptLink(entry.URL)`.
- **yt-dlp** (`ytdlp.List`, `listArgs`, `parseList`):
  - The command is `-J --flat-playlist --extractor-args
    youtubetab:approximate_date -I 1:<n+5> <target>`.
  - Targets:
    - `ytdlp.Search(q, n)` gives `ytsearch<n+5>:<q>`. The prefix means a
      query is never read as an option.
    - `ytdlp.Uploads("@h")` gives `https://www.youtube.com/@h/videos`
      (path-escaped). The Videos tab has no Shorts or streams.
  - **`-I` is essential for channels.** A tab is a lazy generator of
    pages, and `PlaylistEntries` only pulls as many as `-I` asks for.
    Without it, yt-dlp pages through the whole channel.
    `TestLiveBigChannelStopsAtN` guards this.
  - **5 spare** (`spare`): `parseList` keeps, in order, the first n entries
    that are single videos, not `is_live` or `is_upcoming`, not private,
    members-only, premium or needs-auth, and not duplicates.
  - `ytdlp.output` is the shared run-and-buffer code, so `ytdlp.Wait`
    covers lists too.
- **"3 weeks ago":** flat entries have no date. `approximate_date` turns
  YouTube's "N units ago" into `now − N units`.
  - yt-dlp rounds that half up: seconds, minutes and hours to their unit,
    and days or longer to midnight UTC (months and years in calendar
    months).
  - So it must be rounded back, not truncated: "13 years" can come back as
    12 years 364 days.
  - `human.Ago` lets each unit take over half a unit early, and lets the
    mark the rounding left (on the hour, at midnight) settle overlaps.
  - "Ago" counts from the `epoch` that `-J` writes, which is yt-dlp's own
    clock. Our clock after exit runs about 1 s later, which made counts
    one too high near half-unit marks.
  - `human_test.go` replays yt-dlp's arithmetic for every count of every
    unit. Accepted misreads:
    - A "1 month" under 28.5 days reads as "4 weeks".
    - About 1 in 60 (or 1 in 24) seconds, minutes or hours land on the next
      unit's mark and read as 1 of that unit.
- **The screen** (`internal/tui/list.go`):
  - Its quit keys are off (`DisableQuitKeybindings`): its `tea.Quit` would
    skip mindful-yt's exit code, last screen and stopping yt-dlp. `/` and
    `?` are off too.
  - Its colours are replaced with mindful-yt's 212 pink and faint. The
    list's hex defaults are for dark terminals.
  - Rows are worked out once, in `newResults`, so "ago" holds still.
  - `oneLine` turns control characters into spaces.
  - **Keys:** ↑/↓ (they cross pages), ←/→ page (shown only when paged),
    enter picks, **esc goes back to the box with the query kept**, q quits.
  - Esc on the spinner cancels yt-dlp. A late answer is ignored, using
    `listings` plus a stage check.
  - **Height:** an inline frame is `Count("\n")+1` rows, and one taller than
    the terminal loses its top. The list pads to its set height, so
    `sizeResults` sets exactly 3 rows a video when everything fits in
    `height − 6`, and whole pages plus the dots otherwise. It assumes 24
    rows before the first WindowSizeMsg, which gives 5 a page.
- **Errors** go back to the box with the query kept: `Couldn't search
  YouTube: …`, `No videos found for "q".`, `There's no channel @h on
  YouTube.` (a 404), `Couldn't list @h's videos: …`.
  - Problem lines wrap to the terminal (`ansi.Wrap`).
  - The link and reason boxes shrink to fit narrow terminals.
- **Dependencies:**
  - `github.com/sahilm/fuzzy` comes in with bubbles' list (its filter,
    unused).
  - `ultraviolet` is pinned ahead of Bubble Tea (below).

## Measured live, through the proxy (2026-10-03)

- **Search:** one request returns 20 entries, in about 1.9 s.
  - Drops were 0–2 per 20, all live streams, with no duplicates or Shorts.
  - Only the live entries lacked views or dates.
  - A nonsense query gives `entries: []` and exit 0.
  - So n + 5 = 20 is a single request for the default 15.
- **Channels:** `-I 1:20` costs just the channel page (0 continuations),
  about 1.6 s, newest first.
  - Views were on 18/20 (Lofi Girl) and 20/20 (MBCkpop), with dates and
    lengths on all.
  - A missing handle exits 1 with `HTTP Error 404: Not Found`.

## The renderer bug: `ultraviolet` pinned

- **The symptom:** the old frame's top lines stayed on screen whenever a
  frame got shorter (esc from the results, the screen after the ffmpeg
  install).
- **The cause:** in inline (relative-cursor) mode, `move` in
  `ultraviolet` v0.0.0-20260811164956 (Bubble Tea v2.0.10's pin) clamped
  the remembered cursor row to the shorter buffer. The cursor-up then came
  up short.
- **The fix:** v0.0.0-20261001125412-878653296cfd stops the clamp. The user
  chose to pin it (with `go-runewidth` 0.0.30 and `xo/terminfo` 1.0.0).
  AGENTS.md says to keep it until a Bubble Tea release requires it.
- **To reproduce without the network:** a fake `yt-dlp` script in a temp
  `MINDFUL_YT_HOME`, printing canned `-J` JSON, driven in tmux at 80×24.
