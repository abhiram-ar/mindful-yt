# Releases and install scripts

Users shouldn't need Go. A `v*` tag builds release binaries, and a one-line
script per OS installs the right one. mindful-yt then installs yt-dlp, Deno and
ffmpeg itself, as before.

## How it fits together

- `.github/workflows/release.yml`: on a `v*` tag, it runs gofmt, vet (Linux,
  Windows and macOS) and the tests, then GoReleaser.
- `.goreleaser.yaml`: builds `windows`, `darwin` and `linux` for `amd64` and
  `arm64`, with `-X main.version`. Archives are `.tar.gz`, or `.zip` for
  Windows.
  - Archive names carry no version (`mindful-yt_<os>_<arch>`), and the checksum
    file is always `checksums.txt`. That lets the scripts use
    `releases/latest/download/<name>` with no API calls or JSON parsing.
    Keep the names stable.
- `install.sh` (macOS and Linux, POSIX sh, tested under dash) and
  `install.ps1` (Windows PowerShell 5.1+) are served raw from `main`. Each
  one works out the OS and CPU, downloads the archive and `checksums.txt`,
  checks the SHA-256, and installs.
  - `install.sh` installs to `~/.local/bin` by default. It copies next to the
    target and renames, which also works while mindful-yt is running.
  - `install.ps1` installs to `%LOCALAPPDATA%\Programs\mindful-yt` and adds that
    to the user PATH, keeping its entries unexpanded. A running `mindful-yt.exe`
    gets renamed to `.old` first. The script runs inside one `& { }` block,
    so an error under `irm | iex` never closes the user's window.
  - Environment variables: `MINDFUL_YT_VERSION`, `MINDFUL_YT_INSTALL_DIR`, and
    `MINDFUL_YT_BASE_URL` (a local `dist/`, for tests). `install.ps1` also takes
    `MINDFUL_YT_NO_PATH=1`.
- `mindful-yt --version` prints the release version. A `go install ...@vX` build
  shows the module version, and a dev build shows the git pseudo-version.

## Tested locally

- `goreleaser check`.
- `goreleaser release --snapshot --clean`: all six archives and
  `checksums.txt`.
  - On this machine it needed `GOTMPDIR` inside the scratchpad and
    `--parallelism 2`. Otherwise a parallel `go build` loses its `%TEMP%`
    work folder.
- Both scripts, against `dist/` through `MINDFUL_YT_BASE_URL`:
  - a fresh install, run piped into `sh` or through `Invoke-Expression`,
  - a second run over it,
  - a tampered checksum, which was refused with nothing installed,
  - a missing file, which was refused.

## install.ps1 broke when pasted at a prompt (fixed 2026-10-01)

**The failure.** The user pasted the README's two lines and got
`mindful-yt install: unsupported CPU`, with nothing after "CPU". The v0.3.0
tests above all passed because they ran the script from a file.

**Why.**
- The script read the CPU from
  `[Runtime.InteropServices.RuntimeInformation]::OSArchitecture`.
- An interactive PowerShell 5.1 session loads PSReadLine 3.0. PSReadLine
  defines its own `System.Runtime.InteropServices.RuntimeInformation`, which
  has only `OSDescription`. (It also defines `OSPlatform`.)
- PowerShell resolves the type name to PSReadLine's type instead of
  mscorlib's. Reading a static property that doesn't exist returns `$null`
  without an error, so the `catch` fallback never ran.
- A `-File` run doesn't load PSReadLine, so it resolves to mscorlib's type and
  works.

**The fix.** The script now reads `PROCESSOR_ARCHITECTURE` from
`HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Environment`, which
holds the machine's real CPU even in a 32-bit or emulated PowerShell. The
`PROCESSOR_ARCHITEW6432` and `PROCESSOR_ARCHITECTURE` environment variables
are the fallback.

**Tested.** Pasted at a prompt (64-bit, and 32-bit PowerShell), and as a
script file. None of the script's other type literals are shadowed by
PSReadLine.

**The user then installed for real** with the fixed local script
(`Get-Content -Raw install.ps1 | iex`), so the PATH edit has been tested too:
- The value stayed `REG_EXPAND_SZ`, and `%USERPROFILE%\go\bin` stayed
  unexpanded.
- The new folder was appended at the end.
- The temporary `MINDFUL_YT_INSTALL` variable was removed.

Because the folder goes at the end, an older `mindful-yt` earlier on PATH
still wins. The user's dev `bin` folder is one, until they remove it.
